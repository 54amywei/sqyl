# 对公业务全景 · 哈尔滨分行（移动端数据看板）需求与设计方案

## 1. 项目背景与建设目标

### 1.1 业务背景
为满足哈尔滨分行对公业务管理层、支行负责人及一线客户经理在移动场景下随时掌握经营动态的需求，建设一款轻量级、高颜值的移动端对公业务全景驾驶舱。实现“核心指标一屏总览、实时存款动态追踪、业绩排名多维对比、全行到账户五级穿透、营销日报与开门红战报一站直达”。

### 1.2 核心建设目标
* **移动优先，随时随地访问**：深度适配 iOS Safari、Android Chrome 及微信内置浏览器，兼顾 360px 窄屏与全面屏安全区。
* **极简轻量，零依赖秒开**：采用单文件 HTML 架构，无外部字体或框架 CDN 依赖，支持本地离线演示及 GitHub Pages 公开托管。
* **数据可视化与穿透分析**：提供直观的柱线组合趋势图、多维度机构/人员排名及 5 级逐级下钻能力，支撑从宏观管理到微观客户经理督导的业务闭环。
* **视觉专业，金融质感升级**：统一金融深蓝视觉基调，重点打造“报表中心”12 枚定制双色微立体图标与“开门红”红金战报专题，提升客户与内部汇报体验。

## 3. 核心功能模块详细说明

### 3.1 顶部导航与全局筛选
* **顶部吸顶导航**：采用金融深蓝渐变背景，内嵌半透明胶囊容器承载 **存款 / 贷款 / 客户 / 报表中心** 4 个主业务页签；选中态以纯白高光胶囊呈现。切换逻辑基于纯 JS 状态管理，不修改 URL `#hash`，彻底避免微信浏览器返回键错乱。
* **全局数据日期联动**：日期胶囊默认展示 T-1 日期（如 `2026/11/25`），点击可唤起系统原生日期选择器，切换日期后自动按比例重算并刷新当前页所有指标卡、存款结构、走势图与机构排名。

### 3.2 存款模块（默认首页）
1. **开门红战报入口横幅**：绯红渐变横幅配 `HOT` 鎏金标签，点击直达开门红全屏战报。
2. **核心指标区（2列 + 全宽动态横幅）**：
   * **T-1 静态指标卡**：展示「对公存款余额」「对公存款日均」，内置 `T-1` 角标及 **比上日 / 比上月 / 比上季 / 比上年** 四维对比（红涨绿跌）。点击卡片切换高亮态，并联动刷新下方走势图与排名表。
   * **全宽实时对公存款横幅**：跨两列全宽展示实时余额、较昨日增量、今日累计新增、迷你折线图（Sparkline）及更新时间；支持 **每 15 秒自动静默刷新** 与右上角 **一键手动刷新**。
3. **存款结构（2×2 宫格）**：展示「一般性存款」「活期」「结贷比」「保证金」四项结构指标及其比上日变动值。

### 3.3 贷款模块
* 展示「对公贷款余额」「对公贷款日均」两张核心指标卡（含四维对比），支持点击切换选中指标，下方同步联动展示贷款走势图及各维度排名表。

### 3.4 客户模块
* **对公客户汇总条**：3 列居中展示「对公客户总数」「有效客户占比」「人均有效户」。
* **客户指标卡**：展示「对公有效客户」「对公基础客户」，除四维对比外，底部增加**目标达成进度条**可视化展示。

### 3.5 交互式走势图（存/贷/客通用）
* **双轴组合展示**：蓝色渐变柱状图展示「余额/户数」，琥珀黄折线图展示「日均」，标题自动同步当前选中的指标名称与数据日期。
* **触控交互 Tooltip**：支持手指轻触或点击任意柱状节点，当前列高亮显示并弹出深色毛玻璃浮层（Tooltip），精确展示该时段的余额与日均数值；点击空白处自动收起。

### 3.6 多维度排名与 5 级逐级下钻（存/贷/客通用）
* **4 维机构/人员切换**：支持 **支行 / 经营单位 / 办公室 / 客户经理** 四个统计维度一键切换。
* **5 种排序规则**：支持按 **余额 / 比上日 / 比上月 / 比上季 / 比上年** 排序，同时支持点击表头「余额 ↕ / 增量 ↕ / 增速 ↕」快捷排序；前三名配金、银、铜徽章。
* **5 级穿透下钻抽屉**：点击底部「查看全行汇总并逐级下钻」或点击表格任意一行，从底部滑出半屏抽屉，完整支持 5 级逐级下钻：
  > **全行汇总 → 机构/部门 → 员工（客户经理）→ 对公客户 → 具体账户**
* **抽屉内信息与交互**：包含面包屑路径导航、当前层级核心数值卡、5 项对比与完成度宫格、近六期迷你柱状图、下级明细列表；支持点击「‹ 返回」逐级回退，或按住抽屉头部手势下拉收起。

### 3.7 报表中心（4 大分组 · 12 项报表）
以卡片分组承载全行 12 项常用营销日报与专题报表，点击任意图标即可弹出**报表明细抽屉**（专题战报则进入全屏模式）：

| 模块分组 | 图标主题色 | 包含报表 / 入口清单 |
| :--- | :--- | :--- |
| **专题战报（1项）** | 绯红鎏金 | 对公开门红 · 8 项核心指标（横版高亮卡片，带 `HOT` 角标） |
| **存款模块（5项）** | 宝石蓝 | 实时经营单位对公存款（带呼吸绿点「实时」微标）、对公一般性存款营销日报（机构）、客户经理对公一般性存款营销日报（员工）、对公活期存款营销日报（机构）、客户经理对公活期存款营销日报（员工） |
| **客户模块（3项）** | 雅致靛紫 | 对公有效户营销日报（机构）、对公客户经理有效户营销日报（员工）、非对公客户经理对公有效户营销日报（员工） |
| **业务主题（3项）** | 翡翠青 | 大额动账、对公客户存款变化、对公客户贷款变化 |

* **明细表格体验**：报表抽屉表格支持**首列冻结（`position: sticky; left: 0`）**横向流畅滑动，右侧配有渐变遮罩提示可继续右滑查看完整字段。

### 3.8 开门红全屏战报专题
* **全屏沉浸式红金战报**：从首页横幅或报表中心进入，覆盖全屏并锁定底层页面滚动。
* **5 大子页签**：
  1. **核心指标**：展示 8 项开门红核心指标发布进度条（8/8，100%）与 2 列卡片网格（对公存款余额、对公存款日均、对公活期存款余额、对公活期存款日均、公司纯贷款余额、对公有效户、服务实体经济用信户、新开发基础客户）。
  2. **存款 / 客户 / 资产 / 结构战报**：四张完整经营单位战报表，均支持**首列冻结横向滚动**，并以 **黄色（进度达标）、绿色（低于目标/负增长）、橙色（重点关注）** 三色语义高亮单元格。

## 4. 视觉与图标设计规范

### 4.1 色彩体系
* **品牌主色（金融深蓝）**：顶部栏与选中指标卡采用 `#0F2B75 → #1D49B8 → #2F68E5` 多段线性渐变。
* **页面背景与卡片**：浅蓝灰底色 `#EEF2FA` 配纯白卡片 `#FFFFFF`（16px 圆角 + 极浅冷蓝阴影）。
* **金融语义色**：遵循国内金融习惯，上涨/正向为赤红 `#D92D2D`，下跌/负向为翠绿 `#0C9463`，持平为中性灰蓝 `#7C87A8`。
* **数字排版**：全局金额、百分比、排名数值强制开启 `font-variant-numeric: tabular-nums` 等宽数字，确保多行对齐与实时刷新时不发生左右抖动。

### 4.2 报表中心图标设计规范
12 枚图标均采用 **`52×52` 超椭圆（16px 圆角）微立体玻璃拟态**设计，叠加顶部柔和反光高光层与内描边，内部采用 12 套独立绘制的双色 SVG（半透明白色填充层 + 纯白圆润线条层），按四大业务模块区分色系：
* **专题战报（绯红鎏金）**：`#F25C54 → #CF2334 → #9D1222`
* **存款模块（宝石蓝）**：`#528BFF → #2A5EE0 → #193FA8`
* **客户模块（雅致靛紫）**：`#818CF8 → #5B50E6 → #3F34B8`
* **业务主题（翡翠青）**：`#2DD4BF → #0EA5A0 → #0D7477`

## 5. 移动端深度适配与技术实现方案

| 适配维度 | 具体技术实现方案 |
| :--- | :--- |
| **零依赖单文件架构** | 纯原生 HTML + CSS + Vanilla JS 单文件交付，不依赖外部 CSS/JS/字体 CDN，离线打开或弱网环境均可毫秒级首屏渲染。 |
| **多端与安全区适配** | 采用 `100dvh` 动态视口高度与 `viewport-fit=cover`，头部与抽屉/战报底部自动注入 `env(safe-area-inset-top / bottom)` 避让刘海屏与底部手势条。 |
| **桌面端预览兼容** | 屏幕宽度 `< 520px` 时 100% 铺满手机屏幕；宽度 `≥ 520px`（PC 演示时）自动居中呈现 `430px` 精致手机预览壳。 |
| **防 iOS 缩放日期控件** | 在自定义日期胶囊上覆盖 `opacity: 0` 且 `font-size: 16px` 的原生 `<input type="date">`，既保证视觉美观又彻底杜绝 iOS 聚焦输入框时页面自动放大。 |
| **触控热区与防误触** | 所有可点击按钮与表单控件满足移动端触控热区规范（高度 36px～46px），启用 `touch-action: manipulation` 消除 300ms 点击延迟，移除原生高亮闪烁。 |
| **抽屉手势与滚动锁** | 抽屉与全屏战报打开时为 `body` 添加滚动锁防止底层穿透；抽屉头部绑定原生 Touch 手势监听，向下拖拽超过 `80px` 自动平滑收起。 |
| **宽表格首列冻结** | 报表抽屉与开门红战报宽表统一采用 `border-collapse: separate` + 首列 `position: sticky; left: 0` 冻结，搭配右侧渐变遮罩明确引导横向滑动。 |

## 6. 部署托管与后续演进建议

### 6.1 演示与版本托管方案（GitHub Pages）
1. 将单文件重命名为 `index.html`，推送至 GitHub 公开仓库（`main` 分支根目录）。
2. 在仓库 `Settings -> Pages` 开启部署，即可获得专属 HTTPS 链接，支持手机浏览器与微信直接访问。
3. 每次更新后通过 Git Commit 覆盖 `index.html` 并打版本标签（如 `v1.0`、`v1.1`），微信端可通过 URL 拼接 `?v=1.1` 绕过缓存。

### 6.2 生产环境演进建议
* **真实数据对接**：将前端内置的模拟数据集（`M`、`BRANCHES`、`KR_CORE`、`repConfig`）替换为后端 RESTful API / 行内 BI 接口调用，保留现有渲染与下钻交互逻辑。
* **权限与安全管控**：正式上线行内环境时，接入企业微信 / 移动办公门户 SSO 单点登录，按当前登录人角色（分行领导 / 支行行长 / 客户经理）动态控制可见机构范围与数据脱敏粒度。
* **数据导出与分享**：后续可按需扩展战报长图生成（Canvas 截图）与 Excel 导出功能，进一步便利晨会汇报与微信群播报。
